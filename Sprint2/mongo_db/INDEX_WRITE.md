# Влияние индекса на запись и хранение

## Эксперимент

Коллекция — `request_events`. Сравниваются исходные индексы и дополнительный индекс `{ "author.pg_employee_id": 1, "created_at": -1 }`.

Для каждого варианта выполнены один прогрев и пять измерений. Каждый прогон использует свежую временную базу и одинаковые 20 000 документов. Вставка выполняется партиями по 1 000. Порядок вариантов чередуется. Время создания индексов исключено из замера.

После вставки проверяются количество документов и индексов. Перед получением `collStats` выполняется `fsync` вне замера времени. Эксперимент предназначен для отдельного тестового сервера.

Стенд — MongoDB 9.0.4, локальный Replica Set из одного узла. Настройки подключения — `primary`, read concern `majority`, write concern `majority`.

## Результаты

В таблице приведены медианы пяти прогонов. Во всех прогонах записано 20 000 документов.

| Показатель | Исходные индексы | С дополнительным индексом |
|---|---:|---:|
| Время вставки, мс | 221,89 | 256,91 |
| Скорость, документов/с | 90 135,70 | 77 847,52 |
| Размер документов, байт | 3 580 000 | 3 580 000 |
| Выделенное место для данных, байт | 704 512 | 704 512 |
| Размер индексов, байт | 1 191 936 | 1 794 048 |
| Количество индексов | 3 | 4 |

Дополнительный индекс увеличил время вставки на **15,8%** и размер индексов на **602 112 байт (588 КиБ)**. Размер документов сохранился. Это стоимость поддержки индекса, ускоряющего поиск событий сотрудника.

## Запуск

Из `Sprint2/mongo_db` с заданным `MONGODB_URI` тестового сервера:

```bash
go run . index-write > index_write_result.json
```

Код — `index_write.go`.
