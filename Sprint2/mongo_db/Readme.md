# Документная модель MongoDB

В базе `service_center` используются четыре коллекции из [README спринта](../README.md#распределение-данных-между-postgresql-и-mongodb).

| Коллекция | Данные |
|---|---|
| `equipment_models` | Модели техники, их характеристики и типовые неисправности |
| `parts_catalog` | Атрибуты деталей и ссылки на совместимые модели |
| `diagnostic_reports` | Подробные протоколы диагностики со списками проверок |
| `request_events` | События заявки с датой, автором и деталями события |

## Связи и способ хранения

- **1:N.** У одной заявки может быть несколько протоколов диагностики. Каждый протокол содержит `pg_request_id` заявки из PostgreSQL и свой номер `revision`.
- **M:N.** Одна деталь подходит к нескольким моделям, а одной модели подходят несколько деталей. В массиве `compatible_model_ids` хранятся идентификаторы моделей из `equipment_models`.
- **Встраивание.** Массив `checks` хранится внутри протокола. Проверки читают и записывают вместе с протоколом, а при повторной диагностике создают новую ревизию. Чек-лист обычно состоит из 5–30 коротких записей, поэтому мало увеличивает размер документа.
- **Ссылка.** По идентификатору модели можно найти совместимые детали одним запросом. Характеристики модели читаются по необходимости и обновляются в одном документе. Идентификаторы занимают меньше места, чем копии карточек моделей в каждой детали.

## Запуск

Запусти MongoDB и выполни из этой папки:

```bash
go run .       # создаёт коллекции и индексы
go run . demo  # показывает связи на примере
```

По умолчанию программа подключается к `mongodb://localhost:27017`. Другой адрес можно задать через `MONGODB_URI`. Демонстрация создаёт временную базу и удаляет её после запуска. Идентификаторы PostgreSQL в примере условные.
