# Отчёт: Воспроизведение и устранение deadlock в PostgreSQL

## Цель работы

Воспроизвести взаимную блокировку транзакций (deadlock), определить причину её возникновения и проверить способ устранения.

## Ход работы

1. Подключились к базе данных `service_center` в PostgreSQL 16.
2. Выбрали две записи таблицы `part` с `id = 2001` и `id = 2002`.
3. В двух подключениях начали транзакции, изменяющие эти записи в противоположном порядке.
4. Получили ошибку:

   ```text
   ERROR: deadlock detected
   ```

5. Установили причину: каждая транзакция ожидала освобождения строки, заблокированной другой транзакцией.
6. Выполнили ROLLBACK для отмены неудачной транзакции.
7. Проверили обновление записей в одинаковом порядке: сначала id = 2001, затем id = 2002. Команды UPDATE завершились успешно.
Решение
Для предотвращения рассмотренного deadlock необходимо изменять записи в едином порядке во всех транзакциях:

```SQL
BEGIN;

UPDATE part SET price = price + 1 WHERE id = 2001;
UPDATE part SET price = price + 1 WHERE id = 2002;

COMMIT;
```

Вывод
Взаимная блокировка была воспроизведена, а её причина установлена. Она возникла из-за противоположного порядка блокировки строк двумя транзакциями. Использование единого порядка изменения записей помогает предотвратить такой сценарий deadlock.
