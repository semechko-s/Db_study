# Бизнес-правило № 9: защита от двойного резервирования

## Конкурентное выполнение

Для тестирования использовалась запчасть с ID 4 и складским остатком 1.

Первая транзакция зарезервировала одну единицу запчасти для ремонта № 4 и завершилась успешно.

Вторая транзакция попыталась зарезервировать ту же запчасть для ремонта № 5. PostgreSQL отклонил операцию с ошибкой:

`Недостаточно запчастей: доступно 0, запрошено 1`.

После отката второй транзакции остался один активный резерв. Складской остаток не стал отрицательным.

## Реализация защиты

В миграции 003 добавлен триггер `trg_check_part_reservation_stock`, который блокирует строку запчасти с помощью `SELECT ... FOR UPDATE` и проверяет суммарное количество активных резервов.

## Оптимизация запросов

Для сравнения использованы два запроса:
1. Подсчёт активных резервов конкретной запчасти.
2. Получение списка активных резервов с информацией о ремонте и заявке.

В миграции 004 добавлены индексы:
- `idx_part_article` — для поиска запчасти по артикулу.
- `idx_part_reservation_active_reserved_at` — для активных резервов, отсортированных по дате резервирования.

Планы выполнения до оптимизации сохранены в `reports/performance_before.txt`, после оптимизации — в `reports/performance_after.txt`.

## Вывод

Защита от двойного резервирования реализована на уровне PostgreSQL. Дополнительные индексы предназначены для ускорения поиска запчастей и чтения активных резервов. Фактический эффект оптимизации оценивается по времени выполнения и использованию буферов в планах EXPLAIN ANALYZE.
