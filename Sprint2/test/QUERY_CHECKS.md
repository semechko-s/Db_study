# Автоматические проверки аналитических SQL-запросов

Из каталога `Sprint2/test` выполните:

```bash
make query-check
```

Команда пересоздаёт только указанную тестовую БД (по умолчанию
`service_center_test`), применяет миграции, загружает базовые и дополнительные
тестовые данные, а затем в **одном подключении PostgreSQL**:

1. создаёт временные представления с фактическими запросами из
   `queries/business_queries.sql`;
2. выводит результаты этих запросов;
3. запускает `automated_query_checks.sql`, который сравнивает результаты
   представлений с точными ожидаемыми строками.

Проверяются все восемь запросов:
1. заявки в ремонте;
2. выполняющиеся работы и ремонты;
3. активные резервы запчастей;
4. количество заявок и предварительная стоимость по клиентам;
5. оплаченные суммы с порогом `5000.00`;
6. рейтинг мастеров и доля стоимости ремонтов;
7. помесячные оплаты, `LAG`, изменение выручки, накопительный итог и скользящее среднее;
8. история статусов, `LEAD` и длительность статуса.

Проверки используют двустороннее сравнение `EXCEPT ALL`: проверяется не только
наличие строк, но и отсутствие лишних строк, а также точное совпадение значений.
Для запроса №5 тестовые суммы `5500` и `4500` проверяют обе стороны порога `5000`.

Тестовые даты зафиксированы в январе и феврале 2026 года. Поэтому результаты
оконных функций и длительность статуса не зависят от даты запуска. Для перехода
статуса ожидается длительность ровно `2.50` часа.

Если хотя бы одна проверка завершается неуспешно, SQL-скрипт вызывает ошибку,
а `make` возвращает ненулевой код завершения.

Можно задать отдельное имя тестовой БД и параметры подключения:

```bash
make query-check TEST_DB=my_service_center_query_test PSQL_HOST=localhost PSQL_PORT=5432 PSQL_USER=my_user
```

**Внимание:** цель `query-check` удаляет и создаёт заново только базу,
указанную в `TEST_DB`. Не указывайте в `TEST_DB` рабочую базу `service_center`.
